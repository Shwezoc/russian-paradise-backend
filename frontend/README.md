# RUSSIAN PARADISE — Demo v0.4

Мобильный интерактивный frontend-прототип для браузера и Telegram Mini App.

## Запуск без сборки
Из корневой папки проекта запусти:

```sh
python -m http.server 5000 --bind 0.0.0.0 --directory frontend
```

Открой `http://127.0.0.1:5000`. Сборка и установка пакетов не нужны. Локальный браузерный режим работает без Telegram и сохраняет игровой прогресс на этом устройстве.

Для авторизации страница должна быть опубликована по HTTPS и открыта именно внутри Telegram Mini App. Обычный локальный адрес не предоставляет Telegram `initData`; не подставляй тестовые или выдуманные данные.

Папку можно также разместить на Netlify/Vercel/GitHub Pages. API bridge в этой копии сохраняет исходный URL backend из v0.4.

## Что добавлено в v0.4
- API bridge (`api.js`) к `https://russian-paradise-backend.onrender.com`.
- Авторизация через `POST /auth/telegram` с Telegram `initData`.
- После авторизации запрашиваются `GET /me`, `GET /inventory`, `GET /auctions`.
- Статус соединения показывается в шапке и профиле; есть кнопка повторного подключения.
- Существующий локальный игровой режим и сохранение не удалены.

## Что пока НЕ синхронизируется
Баланс, покупки, продажа автомобилей/номеров, бизнес-доходы, сделки и аукционные лоты остаются локальными демо-операциями. В v0.4 серверный профиль/инвентарь/аукционы только читаются. Для полноценного мультиплеера нужны серверные endpoint-ы создания предметов и транзакций, атомарные изменения баланса, проверки владельца и защита от повторной отправки запросов.

## Безопасность
Не помещай Telegram bot token, JWT secret или DATABASE_URL в frontend. Telegram `initData` отправляется backend-у для проверки подписи; секреты остаются только на сервере. Для продакшена используй HTTPS.

## Примечание по API
Клиент ожидает токен в одном из полей `access_token`, `token`, `jwt` или `data.access_token` / `data.token`. Если backend возвращает другой формат, нужно подстроить адаптер `api.js` под фактический ответ Swagger.
